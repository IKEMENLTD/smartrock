# 25_スケジューラ・ジョブ設計

詳細設計｜スケジューラ/ジョブ設計

信頼性の中核(NFR-001)。worker + scheduled_tasks

■ ワーカー動作

・node-cronで毎分起動 → processDueTasks(now) を呼ぶ。

・scheduled_tasks WHERE status='scheduled' AND run_at<=now を SELECT ... FOR UPDATE SKIP LOCKED で取得(多重起動耐性)。

・status=running→type別handler実行→成功done/失敗failed(attempts+1, last_error)。

・attempts>=最大(既定5)で failed 固定＋管理者へLINE/メール通知。

■ タスク種別と発生・処理

- type | 登録タイミング | run_at | 処理
- (即時)createKey | 予約作成API内で同期実行 | - | timeLimitコード発行(start-10m〜end+15m)。結果idはwebhookで後埋め。
- send_reminder | 予約作成時 | start_at − 60min | LINEでリマインド＋コード再掲。
- revoke_passcode | 予約作成時 | end_at + 30min | deleteKey(key_idがNULLならスキップ&再試行/警告)。
- send_thanks | 予約作成時 | end_at + 5min | お礼＋次回予約導線。
- expire_unpaid | 決済ありpending時 | 作成 + 15min | 未決済なら自動キャンセル(deleteKey/カレンダー削除)。
⚠ revoke_passcode は switchbot_key_id 依存。webhook未達でidがNULLのままだと削除不能。リトライしても埋まらない場合は『キーパッド上で期限切れ表示の手動削除』を管理者タスクとして通知する運用フォールバックを用意する(Issue #479相当の制約)。

■ パスコード方式の設計判断

・発行は『予約確定時に即時createKey』。直前発行にしない理由＝非同期＆webhook遅延で開始時刻に間に合わないリスクを避けるため。

・有効/無効は createKey の startTime/endTime によるキーパッドのローカル時刻判定に委ねる(クラウド非依存=締め出し回避)。

・コードは6桁ランダム。passcode_name は r{reservationId} で一意化(deviceスコープ)。
