# 16_外部連携仕様

基本設計｜外部連携仕様（最重要）

SwitchBot / LINE / Google / Stripe / Tapo の実仕様と落とし穴

■ SwitchBot API v1.1（鍵・キーパッド）

・認証：ヘッダに token, t(ms), nonce, sign。sign = Base64(HMAC-SHA256(secret, token+t+nonce))。token/secretはアプリのDeveloper Optionsで取得。

・解錠/施錠：POST /v1.1/devices/{deviceId}/commands  body {commandType:command, command:'lock'|'unlock'}。

・パスコード発行：同commands に command:'createKey', parameter:{name(一意), type:'timeLimit', password:'6-12桁', startTime:epoch秒, endTime:epoch秒}。

・パスコード削除：command:'deleteKey', parameter:{id: passcode_id}。

・type種別：permanent / timeLimit(期間限定) / disposable(1回) / urgent(緊急)。本システムは timeLimit を採用。

・Hub必須(Mini/2/3)。レート上限 10,000回/日。name は device内で一意必須。

⚠ 落とし穴①：createKeyは非同期。成功応答に passcode id を含まない。idは『createKey結果のwebhook』でのみ返る。idが無いと後でdeleteKey不可→期限切れコードが蓄積する。必ずwebhookでidを受領し passcodes.switchbot_key_id に保存すること。

⚠ 落とし穴②：施解錠webhook(changeReport)は『誰が解錠したか(コードID/指紋/NFC)』を含まない。本人特定はできない前提で、予約時間帯から access_logs を推定紐付けする。厳密な本人証跡は入口カメラ録画で補完する。

⚠ 落とし穴③：パスコードはキーパッドにローカル保存(=通信断でも解錠可=信頼性◎)。反面、保存件数に上限があるため、終了済コードのdeleteKey(クリーンアップ)を確実に回す。

■ LINE（Messaging API + LIFF）

・LIFF：idTokenを検証し line userId を取得→customers と突合/作成。

・Webhook：POST /api/webhooks/line。x-line-signature をchannel secretでHMAC-SHA256検証。follow/message/postbackを処理。

・プッシュ：/v2/bot/message/push でパスコード案内・リマインド・お礼を送信。

■ Google Calendar（サービスアカウント）

・サービスアカウントを作成し、対象カレンダーに編集権限で共有。

・events.insert で確定予約をミラー、events.delete で取消反映。

・freebusy.query または events.list で『手動ブロック含むbusy』を取得し空き枠計算に反映(FR-007)。

■ Stripe（任意・Should）

・Checkout Session作成→決済完了は /api/webhooks/stripe(Stripe-Signature検証)で受領し reservation を confirmed に。

・未決済予約は pending とし、一定時間で自動取消(scheduled_tasks)。

■ Tapo（カメラ・録画）

・C320WS(屋外/入口・有線LAN推奨)・C225(室内入口側)。RTSP: rtsp://user:pass@<ip>:554/stream1。

・Frigateで常時録画＋動体検知。施術エリアに画角を向けない設置(NFR-005)。

・SD/クラウド/NVR同時併用は2つまで→NVR録画を主、SDを冗長に。
