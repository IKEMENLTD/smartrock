# 11_システム構成

基本設計｜システム構成

全体アーキテクチャと構成要素

■ 構成要素と責務

- 要素 | 役割
- web (Next.js) | 顧客LIFF/予約画面/管理画面の配信＋API/Webhook受信。
- worker (Node) | scheduled_tasks を1分間隔でポーリングし、パスコード発行/削除・通知を実行。
- postgres | 予約・顧客・パスコード・ログ・タスク・Webhookイベントの永続化。
- frigate | Tapoカメラ(RTSP)を常時録画する自前NVR。Webアプリとは疎結合。
- LINE Platform | 友だち/LIFF/プッシュ通知の外部基盤。
- Google Calendar | 予約のミラー先＆手動ブロックの取得元。
- SwitchBot Cloud | Hub経由で鍵/キーパッドを操作。createKey/deleteKey/施解錠webhook。
- Stripe(任意) | 前払い決済とwebhook。
■ 構成図（テキスト/Mermaid）

［顧客のLINE/LIFF］─▶［web:Next.js API］◀─▶［postgres］
                                   ├─▶ Google Calendar API
                                   ├─▶ SwitchBot API (createKey/deleteKey)
                                   ├─▶ LINE Messaging API (push)
                                   └─▶ Stripe(任意)
［worker:node-cron(1min)］─poll─▶［scheduled_tasks］─▶ 上記外部APIを時刻起動で実行
［SwitchBot Cloud］─webhook─▶［web /api/webhooks/switchbot］─▶ passcodes.id 保存 / access_logs 追記
［Tapo C320WS/C225］─RTSP─▶［frigate(NVR)］（Webアプリとは独立、入口のみ録画）
