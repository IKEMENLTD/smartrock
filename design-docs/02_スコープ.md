# 02_スコープ

要件定義｜スコープ

このシステムで『やること / やらないこと』を明示し誤解を防ぐ

■ 対象範囲（やること）

- 区分 | 内容
- 予約 | LINE/LIFFからの空き枠検索・予約・キャンセル。Googleカレンダー連動。任意で前払い決済(Stripe)。
- 通知 | 予約確定/リマインド/終了時のLINEプッシュ通知。パスコード案内の自動送信。
- 入退室 | SwitchBot API による予約ごとの時限パスコード自動発行/失効。施解錠イベントの記録。
- 管理 | 管理者向けダッシュボード（予約一覧・入退室ログ・デバイス状態・パスコード手動再発行・店舗/営業時間/メニュー設定）。
- 録画 | 入口カメラ(Tapo)のRTSPを自前NVR(Frigate)で常時録画。施術エリアは撮影しない構成。
■ 対象外（やらないこと）

・脱毛機本体の制御・予約への組み込み（機器は手動操作前提）。

・会計/確定申告/在庫管理などのバックオフィス基幹。

・顔認証・生体認証による入室（本MVPは暗証番号方式）。映像のAI解析。

・複数フランチャイズ横断の本部管理機能（将来拡張。本書はマルチ店舗の最小対応まで）。

・Tapoカメラ映像のアプリ内ライブ配信（NVR/Frigate側で閲覧する前提）。

⚠ 決済(Stripe)は優先度Should。MVPは『予約のみ・来店時に都度払い or 事前カード登録なし』でも成立する設計とし、決済モジュールは差し替え可能に分離する。
